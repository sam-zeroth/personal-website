# .impeccable.md

Design context for `/impeccable` runs. If you're editing the visuals of
this site, read this first.

## Design Context

### Users

The site is Sam Merkovitz's personal portfolio. Visitors are a mix of:

- **Recruiters & hiring managers** skimming for a fast read on who Sam is.
- **Curious peers** (engineers, founders, builders) who followed a link and
  want to see what Sam's about.
- **Friends / prospective collaborators** who want to grab contact info or
  read an essay.

They arrive on desktop or mobile, look around for under two minutes, and
should leave feeling like Sam is a thoughtful builder with taste — not
"another Linear clone."

### Brand Personality

**Thoughtful · playful · deliberate.** Sam builds AI agent infrastructure
at Zeroth Technology and has a philosophy background. The brand should
read as someone who's technical but curious about mind + meaning, who'd
rather make something memorable than safe.

Three concrete words: **tactile, literate, unhurried.**

### Aesthetic Direction

The site is **a Mac OS Aqua desktop** (early-2000s OS X era) on desktop
and an **iOS 6 skeuomorphic home** on mobile. Everything lives inside
that metaphor:

- Desktop (`/`): pinstripe title bars, traffic-light (red/yellow/green)
  window controls, brushed-metal menu bar, resizable / maximizable windows.
- Mobile (`/`): glossy app icons with inner gloss, linen-textured
  wallpaper, iOS 6 nav bar for app views.
- Writings article pages: full-screen "Mac document" on desktop (paper
  background, Pixelify Sans chrome, Young Serif body); iOS Reader
  aesthetic on mobile (Helvetica nav + Georgia body).

The neural / brain theme that preceded this direction is intentionally
absent — the metaphor carries the personality now.

### Anti-references

- **No Linear / Framer / Vercel default aesthetic.** No Inter, no subtle
  purple gradients, no minimalist SaaS chrome.
- **No generic AI aesthetic.** No cyan-on-dark, no gradient text, no
  neon glow accents.
- **No glassmorphism decoration** (glass is fine where it serves the OS
  metaphor — e.g. the iOS dock blur).
- **No side-stripe borders** as accents on cards/rows. Use full borders,
  tinted backgrounds, or chrome structure instead.

### Typography

- **Display / chrome**: `Pixelify Sans` — pixel-flavored but legible. Used
  for desktop window titles, Mac chrome, and headline text inside windows.
- **Mono / labels**: `JetBrains Mono` — for small caps, file metadata,
  tag chips, clocks.
- **Body**: `Young Serif` — warm serif used for window body copy and
  desktop article reading. On mobile, system Georgia replaces Young Serif
  for article bodies so reading feels iOS-native.
- **Mobile UI**: `-apple-system` / `Helvetica Neue` for all iOS chrome
  (nav bars, app labels, list rows).

### Color

All colors use `oklch(...)`. The palette is deliberately narrow:

- **Desktop wallpaper**: aqua blue gradient (`oklch(0.55 0.12 240)` →
  `oklch(0.3 0.09 230)`) with a noise overlay.
- **Mobile wallpaper**: deep blue-purple radial gradient with a linen
  texture.
- **Window chrome**: brushed-metal grays (`oklch(0.96 0 0)` → `oklch(0.78 0 0)`).
- **Window body**: near-white `oklch(0.96 0.005 240)`.
- **Ink**: `oklch(0.12 0 0)` — never pure black.
- **Accents**: the red/yellow/green traffic lights are the only vivid
  colors on the desktop. Reserve `--hot-amber` for the reading progress
  bar and occasional highlight states.

### Design Principles

1. **Commit to the OS metaphor.** If it wouldn't exist in Mac OS X or
   iOS 6, it doesn't belong. No hybrid "modern" chrome, no breaking the
   illusion with generic web patterns.
2. **One color moment per screen.** The traffic lights. The wallpaper.
   Highlight state. Everything else is ink on paper.
3. **Every detail should feel period-accurate.** Pinstripe gradients,
   inset highlight on the menu bar, 1px hairline separators, text
   shadows on glossy labels. Skeuomorphism isn't a bug — it's the point.
4. **Don't decorate; structure.** Windows, icons, and chrome carry the
   visual weight. Content inside windows is clean and typographic.
5. **Mobile ≠ shrunken desktop.** Phone experience uses iOS primitives
   (status bar, app grid, dock, nav bar, list rows). Desktop uses Mac
   primitives (menu bar, desktop icons, draggable windows, Finder).

## Component primitives (where the metaphor is enforced)

- `src/components/mac/MacWindow.tsx` — the draggable / resizable / maximizable
  window with traffic lights. Use this for anything that should feel like
  an Aqua window.
- `src/components/mac/MacMenuBar.tsx` — the top menu bar with app name +
  clock. Only one menu bar per desktop view.
- `src/components/mac/icons.tsx` — desktop icon set (folder, person,
  briefcase, phone, document, trash). Extend here if you add new icons.
- `src/components/desktop/AquaDesktop.tsx` — assembles the whole desktop
  (icons + windows + menu bar).
- `src/components/phone/PhoneHome.tsx` — iOS home + app views. Add new
  apps by extending the `APPS` list.

If you need a new surface, extend these primitives before reaching for
something new. Different chrome styles across the site break the
metaphor fast.
